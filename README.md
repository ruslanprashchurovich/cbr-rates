# cbr-rates

Автоматический сбор официальных курсов **USD/RUB** и **EUR/RUB** с сайта ЦБ РФ
по расписанию через **GitHub Actions** — бесплатно, без VPS и без вашего компьютера.

Результаты накапливаются в файле [`data/rates.csv`](data/rates.csv), история
изменений видна через git-коммиты.

## Как это устроено

- `fetch_rates.py` — скрипт на Python (только стандартная библиотека, без зависимостей).
  Берёт курсы с официального XML-эндпоинта ЦБ `https://www.cbr.ru/scripts/XML_daily.asp`.
  Если cbr.ru недоступен (он периодически блокирует зарубежные IP, а раннеры GitHub
  находятся за границей) — автоматически переключается на зеркало `cbr-xml-daily.ru`.
- `.github/workflows/fetch-rates.yml` — расписание запуска. GitHub сам поднимает
  виртуальную машину, запускает скрипт и коммитит новую строку в CSV, если курс изменился.
- Курс ЦБ устанавливается **один раз в день**, поэтому скрипт дописывает строку только
  когда дата или значения изменились — дубликатов в CSV не будет, даже если запускать
  его каждые 10 минут.

Формат CSV:

```csv
fetched_at_utc,rate_date,usd_rub,eur_rub,source
2026-08-06T12:00:15Z,2026-08-07,79.5000,92.3100,cbr.ru
```

- `fetched_at_utc` — когда скрипт получил данные (UTC);
- `rate_date` — на какую дату действует курс;
- `source` — откуда взяты данные (`cbr.ru` или зеркало).

## Пошаговая инструкция

### Шаг 1. Проверьте скрипт локально (необязательно, но полезно)

```bash
python fetch_rates.py
```

Должна появиться строка вида `Записано: 2026-08-07 USD=79.5000 EUR=92.3100 (источник: cbr.ru)`
и файл `data/rates.csv`.

### Шаг 2. Создайте репозиторий на GitHub

1. Зайдите на https://github.com/new
2. Имя — например, `cbr-rates`.
3. Видимость — **Public** (важно: у публичных репозиториев минуты Actions
   не ограничены; у приватных бесплатный лимит 2000 минут/месяц, и расписание
   «каждые 10 минут» его превысит; для расписания «раз в день» приватный тоже подойдёт).
4. Ничего не добавляйте (без README, .gitignore, лицензии) — репозиторий должен быть пустым.

### Шаг 3. Запушьте проект

Локальный git-репозиторий уже инициализирован и содержит первый коммит.
Выполните в папке проекта (подставьте свой логин):

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/cbr-rates.git
```

```bash
git push -u origin main
```

При первом пуше GitHub попросит авторизоваться (браузер или Personal Access Token).

### Шаг 4. Проверьте, что workflow работает

1. Откройте репозиторий на GitHub → вкладка **Actions**.
2. Слева выберите **Fetch CBR rates** → справа кнопка **Run workflow** → **Run workflow**
   (это ручной запуск, чтобы не ждать расписания).
3. Дождитесь зелёной галочки (~30 секунд) и откройте лог запуска — там будет видно,
   что записалось и с какого источника.
4. В файле `data/rates.csv` в репозитории появится новая строка (если курс изменился
   по сравнению с уже записанным).

Дальше всё работает само: GitHub будет запускать скрипт по расписанию,
ваш компьютер не нужен.

### Шаг 5. Смените расписание на «раз в день»

Откройте `.github/workflows/fetch-rates.yml` и замените строку с cron:

```yaml
    - cron: "0 14 * * *"
```

Это 14:00 UTC = **17:00 МСК** — к этому времени ЦБ уже опубликовал курс на следующий
день (публикация обычно в 13:30–14:00 МСК по рабочим дням). Cron в GitHub Actions
всегда в UTC, МСК = UTC+3.

Закоммитьте и запушьте изменение:

```bash
git add .github/workflows/fetch-rates.yml && git commit -m "schedule: daily" && git push
```

## Что нужно знать про GitHub Actions по расписанию

- **Время запуска неточное.** GitHub не гарантирует запуск минута в минуту — в часы
  пик задержка может достигать 5–20 минут. Для дневного курса ЦБ это не имеет значения.
- **Автоотключение через 60 дней неактивности.** GitHub отключает расписание в
  репозиториях без коммитов 60 дней. Здесь это не страшно: скрипт сам коммитит данные
  минимум раз в рабочий день, так что репозиторий всегда «активен».
- **Гео-блокировка cbr.ru.** Если ЦБ блокирует зарубежные IP, скрипт сам переключится
  на зеркало — в CSV это будет видно по колонке `source`.
